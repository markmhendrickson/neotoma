# v0.21.4 security release — operator handoff

**Decision (2026-08-07):** ship the two Phase-1 criticals NOW as v0.21.4; Phase 2
(XSS + crypto, all lower-severity and mostly not remotely exploitable) follows as
v0.21.5. Rationale: other operators self-hosting from npm/main are running the
unauthenticated auth bypass right now and cannot fix what they don't know about.

## What's in v0.21.4

- **CRITICAL** Ed25519 forged-key auth bypass — affected `>= 0.3.0, < 0.21.4`
  (every published release; personal-mode REST only). CVSS ~9.8.
- **HIGH** `sort_by`/`snapshot_filters` SQL injection — affected `>= 0.16.0, < 0.21.4`.
  CVSS ~8.1.
- Both fixed, adversarially reviewed (2 rounds), regression-gated (tests verified
  to fail pre-fix), and already deployed + probe-verified on both operator
  instances (personal v12, client v43).

## Note on the affected range

The auth bypass has existed since **v0.3.0** — it is not a recent regression but a
foundational flaw present the entire life of the product. Any operator who ever
exposed a personal-mode instance publicly should assume potential exposure and
audit access logs (see the advisory's Detection section). This raises the stakes
on operator notification (step 5).
