# Neotoma site launch readiness

This runbook covers a **local candidate**. It does not authorize a package release, source merge, production deployment, indexing switch, new account access, or tracking activation. Record the built commit, manifest digest, host configuration, and served responses before changing any public host.

## Candidate matrix

Run `npx tsx scripts/check_site_launch_readiness.ts site_pages preview > artifact-audit.json` after a production-mode preview build. Its JSON contains a file-by-file SHA-256 manifest and pass or block rows with owners and dependencies. Keep that report with the deployment record. The checker verifies every emitted HTML title, canonical and preview noindex, plus preview robots, sitemap and 404 artifact. It does not claim HTTP status, visual quality, or account-side event delivery.

## Build and verify

```sh
NODE_ENV=production SITE_PREVIEW=1 VITE_SITE_PREVIEW=1 npm run build:ui
NODE_ENV=production SITE_PREVIEW=1 VITE_SITE_PREVIEW=1 npm run build:site:pages
SITE_PREVIEW=1 npm run validate:site-export
npx tsx scripts/check_site_launch_readiness.ts site_pages preview > artifact-audit.json
```

Inspect the report's `failures` (must be empty) and manifest digest. Scan the exact exported artifact for home paths, credential-shaped values, private Markdown or environment files before upload. Check representative anonymous routes through the served preview URL: home, install, a Markdown reader, a retained legal page, a retired locale route, and an unknown route returning HTTP 404. Inspect the **hydrated** browser head as well as view source; a preview JavaScript bundle must never restore `index,follow`. Record desktop and phone keyboard and reduced-motion observations separately from source checks.

Preview `robots.txt` disallows crawling and every HTML page carries `noindex`. A crawler blocked by robots may never read that page's `noindex`; the pair is a preview exposure control, not evidence that a previously indexed URL was removed. Check actual index state separately through established search access.

Build production and rollback artifacts independently with production mode. A prior debug or test-mode output is not a rollback artifact. Before a production switch, retrieve the current per-host deployment configuration, verify established command, target, authority, budget, action gates and current review, then verify the deployed revision and HTTP effects from outside the host. Do not infer a 301/308 from a meta refresh or canonical tag.

## Event and outcome contract

| Signal                                                | Meaning                                                                                                                 | Producer                                                      |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| Pageview                                              | One intended SPA path transition or static-reader navigation; URL is a known public path with no query or fragment.     | Existing Umami client when configured                         |
| `cta_click`, `product_nav_click`, `docs_nav_click`    | Interest in a page, tool, or guide.                                                                                     | Existing Umami client when configured                         |
| `funnel_evaluate_prompt_copy`                         | Evaluation prompt copy, segmented by fixed surface.                                                                     | Existing Umami client when configured                         |
| `funnel_install_prompt_copy`, `funnel_preflight_copy` | Install or preflight text copy, segmented by fixed block or harness.                                                    | Existing Umami client when configured                         |
| `outbound_click`                                      | Handoff to a bounded destination class; no URL or link text.                                                            | Existing Umami client or fixed reader adapter when configured |
| Installation / first use / activation                 | **Unknown from site telemetry.** Only an existing authorized product producer with a defined readback can establish it. | Existing product measurement system, if available             |

Keep event names and custom fields stable. Do not send prompt content, source data, emails, credentials, raw links, referrer URLs, or private query strings. Do not add Google Analytics, a cookie banner, a new tracking account, or a scheduler as part of this revision. Compare source behavior with an authorized Umami readback before claiming delivery or conversion.

The static reader loads the established Umami script asynchronously. A click before it finishes loading may be missed, so reader click counts are directional rather than exhaustive. A failed or blocked tracker can also leave a pageview unmeasured; do not interpret missing events as zero visits.

Reader export validation accepts the document serializer's passive HTML elements and the authored SiteChrome elements. It rejects inline SVG, MathML, other foreign namespaces, unexpected attributes and extra scripts; illustrations remain external image assets. The article itself stays usable without JavaScript.

## Manual observation cadence

- **Launch day:** Save build and deployment hashes, canonical host configuration, production robots/sitemap, representative 301/308 and 404 responses, SSL/security headers, anonymous page rendering, event readback, and rollback artifact. Production remains blocked until the separate release and deployment gates are satisfied.
- **Day 1:** Recheck sampled old-to-new URLs, crawl/index coverage in the established Search Console property if accessible, event and error telemetry, and first workflow support reports. Unknown access or small counts remain unknown.
- **Day 7:** Review grouped indexing, redirects, broken links, page performance and fit-evaluation intent. Compare with a real prelaunch baseline only where one was captured.
- **Weeks 4 and 8:** Pool enough observations for a directional review of fit, tool choice, install intent, verified activation and retention. Reuse existing `metric_definition`, `metric_reading`, `prediction`, and `outcome_score` records; label source, denominator, time window, missingness and confidence. Treat rankings and AI visibility as observations, and avoid causal claims from tiny samples. Decide whether a specific next experiment is warranted; do not auto-promote or schedule it.
