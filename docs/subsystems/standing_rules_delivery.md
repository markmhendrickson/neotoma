# Standing rules delivery

Enabled standing rules lead the instructions on every entrance that serves them, in full, under `[STANDING RULES]`, built by one composition in `src/server.ts` so the entrances cannot drift. The legacy MCP `initialize` response carries them in `instructions` and mirrors them in `serverInfo._neotoma.standing_rules`. The 2026-07-28 stateless transport has no `initialize`: `server/discover` leads with the rules only when that same request authenticated, and the rules come from the identity its own credentials resolved to. Discover itself is the probe a client sends before it has a session, so a result built without an authenticated request carries no rule content, only one fixed line naming where the rules are served. `GET /mcp-interaction-instructions` returns the exact `initialize` text for a caller with an accepted Bearer token (response header `X-Neotoma-Instructions-Composition: user`) and the global text, led by the after-authentication notice, otherwise. `neotoma instructions print` prints that composed text when the configured identity authenticates and the global text, led by the after-authentication notice, otherwise, and states which on stderr. On every entrance, a failed rule lookup or an authenticated identity that cannot be resolved is stated as unknown, never as no rules.
