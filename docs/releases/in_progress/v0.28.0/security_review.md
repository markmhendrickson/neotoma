## Findings

- **openapi-security (classifier concern), `openapi.yaml` `correctTransaction`**: only `changes.minItems` (1 → 0) and two descriptions changed. No `security:` block, route, or auth requirement changed. `protected_routes_manifest.json` is in sync (126 routes); `POST /corrections/transaction` stays auth-required.
- **Alternate-path auth (1)**: none. HTTP (`src/actions.ts` `/corrections/transaction`) and MCP (`src/server.ts` `correctTransaction`) both resolve the user through `getAuthenticatedUserId`; body `user_id` is not trusted. Guards are loaded with `getEntityWithProvenance(..., options.user_id)` and are therefore tenant-scoped.
- **Read-oracle risk from compare-only guards**: a guard reports only pass/fail of an expected value, so an agent could probe field values. Mitigated: `enforceAgentCapability("correct", <all participant types>)` in `src/services/correction_transaction.ts:139` includes guard participants, so an agent needs the `correct` grant on the guard's type. A guard must name a declared field; cross-tenant and absent guards fail closed (`fails closed on absent, cross-tenant, wrong-type, undeclared and malformed guards`). The owner can already read their own entities, so owner sessions gain no new read path.
- **Proxy trust (2) / local-dev widening (3)**: no change. No new `remoteAddress`, `X-Forwarded-For`, `Host`, or `LOCAL_DEV_USER_ID` references in the diff. `security:lint` 0 errors; the 138 warnings are pre-existing and not in changed files.
- **Unauth public route (4)**: no new Express routes.
- **Guest-access widening (5)**: no change to `assertGuestWriteAllowed`, `routeAcceptsGuestPrincipal` or guest-token issuers.
- **AAuth downgrade (6)**: none. Capability enforcement is unchanged except that it now covers guard participants (stricter, not looser).
- **Schema registry atomicity (`src/services/schema_registry.ts`)**: not an auth surface. Registration, merge and activation now run in one transaction; refused changes roll back and dispatch no effects. Deactivation failures now throw instead of logging, which is fail-closed.
