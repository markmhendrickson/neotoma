## Findings

_Fill this section before sign-off. One bullet per concern; cite the file:line touched and either the test that covers it or the residual risk._

- **Alternate-path auth / unauth route.** The `src/actions.ts` change is limited to `GET /mcp-interaction-instructions` swapping two helper calls for the shared `composeInstructions`; no route, middleware, or `isLocalRequest` change. Unauthenticated output still carries only the fixed `STANDING_RULES_AFTER_AUTHENTICATION_NOTICE`; no per-user rules or skill names are reachable without credentials. Covered by `tests/integration/instructions_session_index.test.ts` and `standing_rules_stateless_entrances.test.ts`.
- **Download header (#2946).** `GET /sources/:id/content` in `src/actions.ts` now builds `Content-Disposition` via `buildContentDisposition`. The route, its auth, and its user scoping are unchanged. The encoder drops control and format characters (including CR/LF), so a stored name cannot inject a header. Covered by `tests/unit/content_disposition.test.ts` and `tests/integration/source_content_download_filename.test.ts` (newline and double-quote cases).
- **server/discover.** Authenticated discover now composes through `composeSessionInstructions` with the user id from `resolveInstructionLookupUserId`, the same user-scoped lookup as before; the unauthenticated branch uses only the fixed notice.
- **Proxy trust, local-dev widening, guest policy, AAuth.** No change. No new `LOCAL_DEV_USER_ID` references (lint warnings are pre-existing, in files outside this diff).
- **Index content.** Rule titles and skill names pass through `sanitizeStandingRuleInline` and byte clipping, bounded at 2,048 bytes.
