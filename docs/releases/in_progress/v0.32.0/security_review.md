## Findings

- Classifier flagged `src/actions.ts` (auth-middleware concern). The diff there is two edits: `GET /mcp-interaction-instructions` now calls `composeInstructions` and passes no `indexSection`, and `GET /sources/:id/content` builds `Content-Disposition` with `buildContentDisposition`. No auth check, `isLocalRequest`, proxy-trust or guest-gate line changed.
- Alternate-path auth, proxy trust, local-dev widening, guest-access policy and AAuth downgrade: no change. No route is added or re-mounted, no `X-Forwarded-For`, `Host` or `remoteAddress` read is added, no `LOCAL_DEV_USER_ID` reference is added, no guest-token issuer changes.
- Unauthenticated public route: none added. `security:manifest:check` reports 130 routes in sync.
- Session index disclosure: `renderInstructionsIndex` runs only inside `composeSessionInstructions`, which uses the user id resolved from the request's credentials. The unauthenticated `server/discover` build and `GET /mcp-interaction-instructions` pass no index, so rule titles and skill names are not served to unauthenticated callers. The index adds no data beyond what the full `[STANDING RULES]` and `[INSTANCE SKILLS]` blocks already carry for the same principal.
- Download header: `src/utils/content_disposition.ts` drops control and format characters (CRLF, bidi controls), replaces lone surrogates, percent-encodes `filename*` and replaces quote, backslash and `%` in the ASCII fallback. Header injection through a stored file name is closed rather than opened. The route's auth and `user_id` scoping are unchanged.
- `security:lint`: 0 errors, 139 warnings, all existing `local-dev-user-widening` warnings in files this diff does not touch.
- `test:security:auth-matrix`: 18 passed, 1 skipped.
