Treat the diff as if you were an attacker. For every concern below, propose at least one *concrete* request or code path that exercises the failure mode, then either confirm the gate would catch it or describe the missing test.

1. **Alternate-path auth.** Can an unauthenticated external caller reach a privileged path through an alternate channel — a sandbox-mode shortcut, a guest-access widening, an OAuth callback that resolves a non-bearer principal, an MCP transport that re-uses a session token, or a re-mounted Inspector / docs page? List the request shape, the route, and the expected gate.
2. **Proxy trust.** Does any new code trust `X-Forwarded-For`, `Forwarded`, `Host`, or `req.socket.remoteAddress` outside the canonical `forwardedForValues(req)` + `isLocalRequest(req)` helpers? Construct a tunnel-shaped request that defeats the trust check.
3. **Local-dev widening.** Does any new path reference `LOCAL_DEV_USER_ID`, the `assertExplicitlyTrusted` escape hatch, `NEOTOMA_TRUST_PROD_LOOPBACK`, or a `dev` / `sandbox` env shortcut in a way that could leak into production behavior? 4. **Unauth public route.** For every new Express route, confirm it is in `protected_routes_manifest.json` (auth-required) or in the runtime allow-list with a stated `reason`. List any new route here.
5. **Guest-access policy widening.** Does the diff change `assertGuestWriteAllowed`, `routeAcceptsGuestPrincipal`, or any guest-token issuer? Describe the policy delta in plain English and the entity types newly reachable.
6. **AAuth / agent identity downgrade.** Does the diff make it easier to satisfy auth without a verified `aa-agent+jwt`? E.g. a fallback to `clientInfo.name` for a write that previously required `hardware`/`software` tier.

## Findings

Range `v0.26.0..HEAD`. The five-lens panel, security lens included, reviewed the peer sync, agent grant and correction package on its final head with the same requests on REST and MCP under every caller kind (owner, broadly and narrowly granted agents, denied signers, unrecognised signers). Full working detail is kept privately until the advisory publishes.

- **Alternate-path auth / AAuth downgrade.** Agent grants now apply on every entry point that changes data, on REST and MCP. A request naming a type the grant does not cover is refused, and no data of that type is stored. The configured-bearer change (`src/actions.ts`, `src/services/bearer_slots.ts`) takes the same branch on either slot: no new principal, no scope widening. Covered by `tests/integration/entity_mutation_capability_coverage.test.ts`, `tests/integration/flow_mutation_capability_coverage.test.ts`, `tests/integration/bearer_handover_slot.test.ts`.
- **Handover slot misuse.** Bounded to 7 days, fails closed on any malformed configuration, constant-time comparison. Covered by `tests/unit/bearer_slots.test.ts`.
- **Durable credential minting.** `src/services/oauth_key_gate.ts` accepts the primary bearer only.
- **Logging.** No log line or error carries a bearer value or digest. Refusal messages returned to a peer or caller are fixed server text.
- **Proxy trust / local-dev widening.** No new reads of `X-Forwarded-For`, `Host` or `remoteAddress`, and no new `LOCAL_DEV_USER_ID` references on the auth surface.
- **Unauth public route.** No new Express routes. `security:manifest:check`: in sync (126 routes).
- **Guest-access widening.** No widening. Guest-writable routes keep their access policy; denied signers are refused on them.
- **Sync (peer admission).** One admission check runs on every way a peer's data enters an instance, before anything is stored. Governance types need a per-peer opt-in; protected types and `peer_config` are never accepted. Covered by `tests/integration/sync_remote_*`, `tests/services/sync_peer_*`.
- **Store entity type rule.** A structured store requires `entity_type` as a non-empty string on REST and MCP, for every caller kind, before anything is written. Covered by `tests/integration/entity_mutation_capability_coverage.test.ts`.
- **Hosted outbound host check.** Covered by `tests/security/ssrf_host_guard_alternate_loopback_forms.test.ts`.
- **Root landing.** `harness_snippets.ts`, `index.ts` and `site_nav.ts` changes are content and navigation; no change to `isLocalRequest` logic.

## Residual risks

- While a handover window is open, the retiring bearer is a full owner credential for up to 7 days. Mitigated by the cap, boot-time WARN and per-client audit events.
- A grant with `store` or `correct` on `*` also covers `agent_grant` records. This is a recorded design decision, and the release notes ask operators to review such grants.
- Non-blocking follow-ups from the panel are tracked privately and do not hold this release.
- `security:lint` reports 138 warnings and 0 errors, all pre-existing patterns.
