## Findings

- **Alternate-path auth.** The diff (`caa30f8c9`) *removes* an auth branch, not adds one: it drops the bare `!authHeader && !connectionIdHeader → 401` guard on `/.well-known/oauth-protected-resource[/mcp]` and adds an explicit-404 route for `/.well-known/openid-configuration`. All four discovery routes are now correctly declared `security: []` in `openapi.yaml` and regenerated into `protected_routes_manifest.json` with `requires_auth: false`, `expected_no_auth_status: [200, 400, 404, 405]`. No privileged path became reachable — RFC 9728/8414 require these bootstrap documents to be unauthenticated by design, and no non-discovery route changed auth posture. The `X-Connection-Id` invalid-token branch (the real guard against stale-credential replay) is untouched. Verified: `tests/integration/wellknown_discovery_unauthenticated.test.ts` (4 cases) asserts the unauthenticated 200/404 shape.
- **Proxy trust.** No changes to `forwardedForValues`, `isLocalRequest`, or any `X-Forwarded-For`/`Host` read in this diff. `src/actions.ts` changes in this release are limited to route registration and OpenAPI-declared security metadata, not proxy-trust logic.
- **Local-dev widening.** No `LOCAL_DEV_USER_ID` references touched in this diff (pre-existing references in `src/services/sandbox_mode.ts` flagged by `security:lint` are unrelated warnings, not new in this release).
- **Unauth public route.** Two new Express routes: `GET /.well-known/oauth-protected-resource/mcp` and `GET /.well-known/openid-configuration`. Both are declared in `openapi.yaml` with `security: []` and present in `protected_routes_manifest.json` as unauth-allowed by design (RFC 9728 §3.1 resource-suffixed discovery path; RFC 8414-adjacent explicit-404 for an unimplemented OIDC discovery contract). `npm run security:manifest:check` confirms the manifest is in sync (118 routes, no drift).
- **Guest-access policy widening.** No changes to `assertGuestWriteAllowed`, `routeAcceptsGuestPrincipal`, or any guest-token issuer in this diff.
- **AAuth / agent identity downgrade.** No changes to AAuth verification or `clientInfo.name` fallback paths in this diff.
- **fly.operator.toml (88712d97d).** Adds a new Fly deploy config, not application code — declares `restart.policy = 'always'` and explicit VM sizing to prevent silent downsizing on deploy. No auth/request-handling surface; outside the scope of this adversarial review's request-shape prompts. No app name, region, or hostname is hardcoded (both passed at deploy time), consistent with the existing `fly.sandbox.toml` precedent of keeping deployment targets out of the public repo.
- **Homepage proof-stats refresh (4aba1397c).** Frontend-only copy/data change (stat numbers, locale strings, `repo_info.json`). No security surface.

## Suggested negative tests

- Covered: `tests/integration/wellknown_discovery_unauthenticated.test.ts` — asserts all 4 discovery-adjacent requests (bare path, `/mcp`-suffixed path, `openid-configuration`, and following `/mcp`'s own `WWW-Authenticate` redirect) succeed or 404 correctly with **no** `Authorization` and **no** `X-Connection-Id` header, which is the exact shape an attacker with no credentials would send. The test also pins `openid-configuration` to exactly 404 (not merely `!== 401`), so a regression back to a synthetic 200 or an auth-gated 401 would fail.
